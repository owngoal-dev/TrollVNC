## 需求：输出缩放与画质解耦（TrollVNC）

用户诉求：改动「输出缩放」时画质跟着变，要求把画质做成独立选项。

### 关键勘察结论（后续改动请沿用）
- 全工程原本**没有任何服务端画质参数**。`gScale`（`src/trollvncserver.mm:84` 附近）只影响帧缓冲像素尺寸（`maybeResizeFramebufferForRotation()`），画质由客户端 `SetEncodings` 协商的 `cl->tightQualityLevel`（默认 -1）决定。
- 因此「缩放变、画质也变」是单旋钮设计的必然结果，可独立出来的维度是**编码质量**。
- 配置三条入口：CLI `getopt`（optstr 在 `parseCLI`）、`-daemon` 读偏好域 `com.82flex.trollvnc`、`Managed.plist`。
- 设置界面：应用内 `app/.../TVNCRootListController.m` 与「设置」面板共用 `prefs/TrollVNCPrefs/Resources/Root.plist`。`prefs/TrollVNCPrefs/TVNCSliderCell.{h,m}` 是 **git symlink 文本**，真实现在 `app/TrollVNC/TrollVNC/TVNCSliderCell.m`，只改后者。
- 客户端连上后会发 `SetEncodings` 覆盖 `tightQualityLevel`，所以覆盖必须挂在 `gScreen->clientFramebufferUpdateRequestHook` 上每帧重套（`newClientHook` 里设一次不够）。
- `-daemon` 模式在 `parseDaemonOptions()` 后直接 return，getopt 循环不执行 → daemon 下 CLI 参数全部被忽略，只能改偏好。

### 实现（8 文件，+223/-15，未 commit）
- `src/trollvncserver.mm`：`gQualityLevel = -1`（-1 早退=完全跟随客户端，0..9 强制写 `cl->tightQualityLevel`，宏保护 `LIBVNCSERVER_HAVE_LIBZ||LIBPNG`）；`-q auto|-1|0..9`；偏好 `Quality`；cfg 日志加 `quality=%d`；两个静态函数 + 钩子注册。
- `app/.../TVNCSliderCell.m`：新增可选属性 `placeholderWhenUnset` + `valuePlaceholderMatch`，值等于 match 时数值标签显示占位文字（确定性判定，不依赖 `performGetter` 返回 nil）。
- `Root.plist`：Image Quality 组 + 11 格滑块（-1 自动 + 0–9），footer 已含有损警示。
- 两份 `Root.strings`：各 108 条；`Auto` 故意不本地化（cell 直接贴 UILabel，不走 `NSLocalizedString`，加键即死键）。
- `README.md` / `CHANGELOG.md` / `PERFORMANCE.md` 同步。

### 设计取舍（重要）
- 滑块最左格 `-1` = Auto（跟随客户端），默认停最左。原计划纯 0–9 滑块，但「thumb 在 6、标签写 Auto」自相矛盾，且 `PSListController readPreferenceValue:` 可能回落 default 导致 nil 判定失效，故改为 11 格、纯位置判定。
- `segmentCount` 必须整除 range，否则 step 非整数会让精确相等比较失配。

### 遗留风险
- `lib/libvncserver.a` 是预编译产物，`clientFramebufferUpdateRequestHook` 的实际调用时机是否早于编码**只能真机实测**：`-q 6 -V` + Tight 客户端看日志 `Quality: forced tightQualityLevel=6`，并用 `-q 0` vs `-q 9` 对比流量。
- 本机无 iOS 工具链，全部验证为静态 + Python harness（QA 共 ~294 项断言）。
